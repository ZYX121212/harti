1. 项目总览

Harti 是一台桌面互动电子宠物。一只大眼睛显示在圆形屏上，会随你的动作做出表情变化。核心交互：

  • 摇晃 Harti — 它会惊讶或开心
  • 轻拍 桌面 — 它会抬头看你
  • 翻转 Harti — 它会惊恐
  • 捂热 机身 — 它的脸会变暖
  • 碰一碰 另一只 Harti — 两只建立关系（BLE，待实现）
  • 按 BOOT 键 — 切换风格（6 种画风）
指标值
MCUESP32-S3 (240MHz, 双核, 8MB PSRAM, 16MB Flash)
屏幕GC9A01 240×240 圆形 IPS, SPI 3-wire @ 10MHz
IMUMPU6050 I2C @ 0x68, ±8g / ±500dps, 100Hz
温度NTC 10kΩ B=3950, ADC1_CH0 (GPIO0)
触摸ESP32-S3 内置电容触摸 TOUCH0 (GPIO1)
框架ESP-IDF v6.0.1 + LVGL 8.3 + FreeRTOS
语言标准C23 (gnu23), CMake + Ninja

4. 逐文件详解

4.1 main.c — 入口

位置：main/main.c

整个固件的启动入口。职责：

  1. lv_init() + 1ms tick 定时器 — 供 face_animator 使用
  2. gc9a01_init() — SPI 初始化 + 屏幕复位序列
  3. face_init() — 初始化 animator + renderer + micro + prop，设默认 sprite
  4. face_render_frame() — 立即渲染一帧（屏幕先亮）
  5. 创建 5 个 FreeRTOS 任务（display 最先创建，优先级最高）

启动顺序不能乱：LVGL → 屏幕 → 渲染第一帧 → 创建任务。否则开机黑屏。

4.2 harti_config.h — 配置中心

位置：main/harti_config.h

所有可调参数集中在这里。包含：

  • emotion_t 枚举（与 face_model 的 expression_id_t 值一一对应）
  • 5 个 task 的栈大小和优先级
  • IMU 阈值（摇晃、轻拍、翻转、旋转、倾斜）
  • 温度阈值（捂热、低温）
  • 按键消抖参数
  • 行为状态机超时参数
  • 显示帧率

修改任何参数只需改这个文件，重新编译即可。

4.3 app_sensors.c/h — 传感器事件检测

位置：main/app_sensors.c + app_sensors.h

启动 I2C 总线和 IMU，创建 sensor_task（100Hz）。核心函数：

函数作用
sensors_start()创建 event_queue + sensor_task，返回 queue 句柄
process_imu()处理一帧 IMU 数据 → 检测 6 种事件 → 发到 queue
process_temp()每 1s 读一次温度 → 检测捂热/低温 → 发到 queue

sensor_task 每 10ms 执行一次：读 IMU → process_imu → process_temp（后者内部节流到 1Hz）。

4.4 app_behavior.c/h — 行为状态机

位置：main/app_behavior.c + app_behavior.h

创建 behavior_task，从 sensor_queue 读取事件。核心逻辑：

  • on_event()：根据事件类型和 value 决定 transition_to 哪个状态
  • check_idle()：每秒检查一次，超时自动转 BORED → SLEEPY
  • 唤醒机制：BORED/SLEEPY 状态下任何事件先回 IDLE
  • 内部状态 behavior_state_t（IDLE/HAPPY/SURPRISED/...）和对外表情 emotion_t 分离

4.5 app_input.c/h — 物理输入

位置：main/app_input.c + app_input.h

创建 input_task，每 30ms 轮询 BOOT 按键（GPIO0）。按下后切换到下一个 sprite：

VECTOR → LINEART → CLASSIC → CAT → PIXEL → ROBOT → NOVA → PIG → CHIBI → VECTOR → ...

使用双重检测（GPIO 数字电平 + ADC 值）防止误触。sprite 列表通过 sprite_registry 获取，不直接引用各 sprite 头文件。

4.6 app_ble.c/h — BLE 通信

位置：main/app_ble.c + app_ble.h

当前为 stub 实现：只创建 ble_task，每 5s 打印心跳日志。完整 BLE 广播/扫描/配对功能待实现。

6.3 9-pass 渲染层级

for y = 0..239:
  pass 1: sp->draw_face(y)           ← 背景渐变
  pass 2: sp->draw_blush(y)          ← 腮红（叠加在背景上）
  pass 3: sp->draw_mouth(y)          ← 嘴巴（含舌头/牙齿）
  pass 4: sp->draw_eye_left(y)       ← 左眼（虹膜+瞳孔+高光+眼睫毛）
  pass 5: sp->draw_eye_right(y)      ← 右眼
  pass 6: sp->draw_brow_left(y)      ← 左眉
  pass 7: sp->draw_brow_right(y)     ← 右眉
  pass 8: sp->draw_decor_overlay(y)  ← 装饰层（泪滴/星星/汗滴/闪光）
  pass 9: sp->draw_props(y)          ← 道具层（爱心/茶杯/手/星/汗滴）
  gc9a01_send_pixels(line_buf, 240)  ← SPI 推一行

每一行的 9 次 pass 在同一个 line_buf[240] 上叠加（后写的覆盖先写的），实现正确的 Z 序。只用 240×2=480 字节缓冲，而非全帧 115KB。

6.4 表情数据流

face_set_expression(HAPPY)
  → animator_set_expression(1)
    → 从 EXPRESSION_DEFS[1] 读 target + timing
    → 为 7 个 component 各创建 lv_anim_t
      → 每个 component: 从当前值 lerp 到 target 值
        → anim_exec_cb 每帧更新 current_state

face_render_frame()
  → animator_get_state() → 栈上 copy
  → micro_animator_apply(&display_state)  ← 叠加微动画
  → prop_animator_apply(&display_state)   ← 叠加道具动画
  → renderer_render_frame(&display_state)
    → 逐行调用 sprite 的 9 个 draw 函数（传入 face_state_t）

6.8 绘制 Face 的方法详解

本节从零开始讲解如何实现一个 sprite 的绘制函数——理解扫描线渲染模型、坐标映射、用 face_state_t 驱动动态效果，以及各种绘制原语的实现模式。

6.8.1 渲染模型：逐行扫描

Harti 不使用全帧缓冲（240×240×2=115KB 太贵）。每帧渲染是一个双层循环：

outer loop: y = 0 → 239                    ← 240 行
  │
  ├─ 清空 line_buf[240]（全部填底色）
  ├─ pass 1: sp->draw_face(y, ...)         ← 此行背影
  ├─ pass 2: sp->draw_blush(y, ...)        ← 腮红叠在脸上
  ├─ pass 3: sp->draw_mouth(y, ...)        ← 嘴（含舌头/牙齿）
  ├─ pass 4: sp->draw_eye_left(y, ...)     ← 左眼
  ├─ pass 5: sp->draw_eye_right(y, ...)    ← 右眼
  ├─ pass 6: sp->draw_brow_left(y, ...)    ← 左眉
  ├─ pass 7: sp->draw_brow_right(y, ...)   ← 右眉
  ├─ pass 8: sp->draw_decor_overlay(y, ...)← 装饰层
  └─ gc9a01_send_pixels(line_buf, 240)     ← SPI 推一行

9 次 pass 在同一行缓冲区上叠加，后写的覆盖先写的。这是 Z 序的关键——眉毛永远画在眼睛上方，装饰永远在最顶层，道具在最顶层。

6.8.2 绘制函数签名

void draw_xxx(int y, const face_state_t *st, const sprite_set_t *sp, uint16_t *buf);
参数含义用法
y当前扫描行号 (0-239)判断此行是否落在几何体内，计算与几何体的纵向距离
st当前面部状态读取 7 个组件参数，驱动动态效果（眼睑、虹膜、嘴型、眉毛、装饰强度等）
sp当前 sprite 配置读取 eye_radius、eye_half_spacing 等布局参数，以及 pal 调色板
buf240 像素缓冲区直接写入 buf[x] = color，RGB565 格式 uint16_t

6.8.4 基本绘制原语（pattern 速查）

A. 填充圆形

// 在行 y 上画一个填充圆（圆心 cx,cy，半径 r，颜色 color）
static void draw_filled_circle_row(int y, int cx, int cy, float r,
                                    uint16_t color, uint16_t *buf) {
    float dy = (float)(y - cy);
    if (fabsf(dy) > r) return;  // 行在圆外，跳过
    float xspan = sqrtf(r * r - dy * dy);
    int x0 = cx - (int)xspan;
    int x1 = cx + (int)xspan;
    if (x0 < 0) x0 = 0;
    if (x1 >= SCREEN_W) x1 = SCREEN_W - 1;
    for (int x = x0; x <= x1; x++) buf[x] = color;
}

B. 圆环（空心圆 outline）

// 画一个圆环：内半径 inner_r，外半径 outer_r
float dy = (float)(y - cy);
if (fabsf(dy) > outer_r) return;
float outer_span = sqrtf(outer_r * outer_r - dy * dy);
float inner_span = (fabsf(dy) < inner_r)
    ? sqrtf(inner_r * inner_r - dy * dy) : 0.0f;

int x_left   = cx - (int)outer_span;
int x_right  = cx + (int)outer_span;
int x_il     = cx - (int)inner_span;
int x_ir     = cx + (int)inner_span;

// 左半环 + 右半环
for (int x = x_left;  x < x_il;  x++) if (x >= 0)        buf[x] = color;
for (int x = x_ir + 1; x <= x_right; x++) if (x < SCREEN_W) buf[x] = color;

C. 任意厚度线条（基于距离函数）

// 通用的"距离-线宽"判定模式——画曲线最常用！
// half_thick = 线宽的一半（比如 8px 线用 4.0f）
if (fabsf(distance_to_curve) < half_thick) {
    buf[x] = color;
}

这个模式适用于任何几何形状：贝塞尔曲线上的眉毛、二次曲线上的嘴、直线上的胡须——只要能把"点到曲线的距离"算出来就行。

D. 二次贝塞尔曲线（眉毛、嘴型等）

// 三控制点：p0(起点) → p1(曲率控制点) → p2(终点)
// 对给定的 y，求解 t，再求 x = Bx(t), 曲线 y = By(t)
float bez_x_at_y(float x0, float y0, float x1, float y1,
                 float x2, float y2, float y_target) {
    // 用二次公式从 y_target 反解参数 t
    float a = y0 - 2.0f * y1 + y2;
    float b = 2.0f * (y1 - y0);
    float c = y0 - y_target;
    float t;
    if (fabsf(a) < 0.0005f) {
        t = (fabsf(b) < 0.0005f) ? -1.0f : -c / b;
    } else {
        float disc = b * b - 4.0f * a * c;
        if (disc < 0.0f) return -1.0f;
        float sd = sqrtf(disc);
        float t0 = (-b + sd) / (2.0f * a);
        float t1 = (-b - sd) / (2.0f * a);
        t = (t0 >= 0.0f && t0 <= 1.0f) ? t0 :
            (t1 >= 0.0f && t1 <= 1.0f) ? t1 : -1.0f;
    }
    if (t < 0.0f || t > 1.0f) return -1.0f;
    float s = 1.0f - t;
    return s * s * x0 + 2.0f * s * t * x1 + t * t * x2;
}

实际使用时，先调用 bez_x_at_y 得到此行曲线上的 x 坐标，然后用距离判定画线：

float curve_x = bez_x_at_y(inner_x, inner_y, arch_x, arch_y, tail_x, tail_y, (float)y);
if (curve_x >= 0.0f) {
    float half_th = bp->thickness * 1.5f;
    for (int x = x_min; x <= x_max; x++) {
        if (fabsf((float)x - curve_x) < half_th)
            buf[x] = pal[PAL_BROW];
    }
}

E. 带边缘抗锯齿的判定

// 用 edge = fabsf(dist - r) 判断是否在边缘附近
// 边缘距离 < 1.0f → 半透明过渡
float edge = fabsf(r - FACE_R);
if (edge < LINE_HALF) {
    buf[x] = pal[PAL_BG_EDGE];   // 边缘色
} else if (r < FACE_R) {
    buf[x] = pal[PAL_BG];        // 内部填充色
}
// 外部不写 → 保留背景

6.8.5 face_state_t 驱动动态效果

每个绘制函数需要查看 face_state_t 中对应组件的参数，让静态几何体"动起来"。

眼睛绘制 —— 最重要、最复杂的组件

static void draw_eye_impl(int y, const eye_params_t *ep, float eye_r,
                           int eye_cx, int eye_cy, const uint16_t *pal, uint16_t *buf) {
    // 1. 虹膜偏移 —— 眼珠转动
    float iris_dx = ep->iris_center.dx * eye_r * 0.35f;  // 最大移 35% 半径
    float iris_dy = ep->iris_center.dy * eye_r * 0.35f;
    int iris_cx = eye_cx + (int)iris_dx;
    int iris_cy = eye_cy + (int)iris_dy;

    // 2. 上眼皮位置 —— 控制"开合度"
    float lid_open = 1.0f - (ep->top_lid_mid.dy * 1.6f);
    if (lid_open < 0.04f) lid_open = 0.04f;   // clamp，不完全闭合
    if (lid_open > 1.05f) lid_open = 1.05f;

    // 3. 眼皮曲线 —— 用二次函数模拟弧形
    float base_top = -eye_r * lid_open;
    float base_bot =  eye_r * lid_open;

    for (int x = ...) {
        float fx = (float)(x - eye_cx);
        float fy = (float)(y - eye_cy);
        float r_sq = fx * fx + fy * fy;
        if (r_sq > eye_r * eye_r) continue;   // 在眼球外

        // 弧形：根据 x 到中心的距离调整上眼皮曲率
        float arc = 1.0f - (fx * fx) / (eye_r * eye_r);
        float inner_adj = ep->inner_corner.dy * 5.0f;
        float outer_adj = ep->outer_corner.dy * 5.0f;
        float corner_adj = inner_adj + (outer_adj - inner_adj)
                         * ((fx + eye_r) / (2.0f * eye_r));

        float top_lid = base_top + (4.0f * lid_open * arc) + corner_adj * 0.5f;
        float bot_lid = base_bot - (2.5f * lid_open * arc) - corner_adj * 0.3f;

        // 眼皮裁剪：在眼睑外的像素不画（由背景覆盖）
        if (fy < top_lid || fy > bot_lid) continue;

        // 4. 高光点 —— 根据 shine_intensity 控制亮度
        float hl_dist = dist_sq(fx, fy, HL_DX, HL_DY);
        if (hl_dist < HL_R_SQ && ep->shine_intensity > 0.3f) {
            buf[x] = pal[PAL_SHINE];
            continue;
        }

        // 5. 瞳孔 —— pupil_scale 控制大小
        float pupil_r_sq = eye_r * eye_r * 0.15f * ep->pupil_scale;
        if (dist_sq(fx, fy, iris_dx, iris_dy) < pupil_r_sq) {
            buf[x] = pal[PAL_PUPIL];
            continue;
        }

        // 6. 虹膜（眼球白色部分）
        buf[x] = pal[PAL_SCLERA];
    }
}

// ── draw_face: 纯色背景 + 圆脸轮廓 ─────────────────
static void draw_face(int y, const face_state_t *st,
                      const sprite_set_t *sp, uint16_t *buf) {
    (void)st;
    const uint16_t *pal = sp->pal;
    float r2 = 0.0f, face_r = 105.0f;

    // 此行在圆外 → 留底色
    float dy = (float)(y - CENTER_Y);
    if (fabsf(dy) > face_r) return;

    float half_w = sqrtf(face_r * face_r - dy * dy);
    int x_l = CENTER_X - (int)half_w - 1;
    int x_r = CENTER_X + (int)half_w + 1;
    if (x_l < 0) x_l = 0;
    if (x_r >= SCREEN_W) x_r = SCREEN_W - 1;

    for (int x = x_l; x <= x_r; x++) {
        r2 = dist_sq(x, y, CENTER_X, CENTER_Y);
        float r = sqrtf(r2);
        float edge = fabsf(r - face_r);
        if (edge < 4.0f) buf[x] = pal[PAL_BG_EDGE];   // 8px 黑色轮廓
        else if (r < face_r) buf[x] = pal[PAL_BG];     // 白色填充
    }
}

static void draw_eye_left(int y, const face_state_t *st,
                           const sprite_set_t *sp, uint16_t *buf) {
    const eye_params_t *ep = &st->eye[0];
    const uint16_t *pal = sp->pal;
    int ecx = CENTER_X - (int)sp->eye_half_spacing;
    int ecy = CENTER_Y + (int)sp->mouth_y_center - 40;
    float er = sp->eye_radius;
    float lid_open = 1.0f - (ep->top_lid_mid.dy * 1.6f);
    if (lid_open < 0.04f) lid_open = 0.04f;

    float dy = (float)(y - ecy);
    if (fabsf(dy) > er) return;

    float hw = sqrtf(er * er - dy * dy);
    int xl = ecx - (int)hw, xr = ecx + (int)hw;
    if (xl < 0) xl = 0; if (xr >= SCREEN_W) xr = SCREEN_W - 1;

    float base_top = -er * lid_open;

        if (dy < base_top + (4.0f * lid_open * (1.0f - dx*dx/(er*er))))
            continue;         // 上眼皮裁剪
        if (dist_sq(dx, dy, 0, 0) < er * er)
            buf[x] = pal[PAL_PUPIL];   // 全黑填充
    }
}

6.8.8 性能注意事项

事项说明
每一行都在 20fps 下被调用每帧 240 行 × 9 pass = 2160 次函数调用。避免任何堆分配、递归、长循环。
early-out 至关重要每行的第一件事是判断此行是否落在几何范围内——if (fabsf(y - cy) > r) return;。大多数行会立即返回。
避免浮点除法和 sqrtf 在像素循环内平方距离和半径平方的比较可以避免 sqrtf：if (dx*dx + dy*dy < r_sq) 而不是 if (sqrtf(...) < r)
使用 static const 存储常量几何数据固定位置的装饰（胡须坐标、星星位置等）用 static const int[4][2] 定义在函数内，不占用栈空间。
复杂的曲线计算在 per-row 层做如 bez_x_at_y 每行只调用一次（得到曲线 x 坐标），然后在像素循环内只用简单距离判定。
只用 line_buf 不跨行依赖不能访问上一行或下一行的像素。该限制来自扫描线架构——每行独立渲染，SPI 即推即忘。
常见陷阱：sprite 绘制函数是叠加式的——后面的 pass 会覆盖前面的。如果 draw_eye_left 不写边缘外的像素，背景颜色就会自然透出（这是正确的叠层效果）。如果你想在眼睛上"挖洞"，就直接不写那些像素。

7.2 数据流

sensor_task (100Hz)
  └─ imu_read() → imu_data_t {accel[3], gyro[3]}
       └─ process_imu()
            ├─ 存入滑动窗口 accel_history[50][3]
            ├─ 计算动态幅值 dynamic_mag = |mag - 1.0g|
            ├─ 检测 TAP (短脉冲)       → xQueueSend(EVT_TAP)
            ├─ 检测 SHAKE (持续高幅值)  → xQueueSend(EVT_SHAKE)
            ├─ 检测 FLIP (Z轴反向)     → xQueueSend(EVT_FLIP)
            ├─ 检测 TWIST (陀螺Z高速)   → xQueueSend(EVT_TWIST)
            └─ 检测 TILT (持续倾斜)    → xQueueSend(EVT_TILT)

sensor_task (每 100 帧 ≈ 1s)
  └─ temp_read_celsius() → float
       └─ process_temp()
            ├─ 检测 WARM_UP (升温速率) → xQueueSend(EVT_WARM_UP)
            └─ 检测 COLD_DOWN (低温)   → xQueueSend(EVT_COLD_DOWN)

7.3 滑动窗口机制

IMU 事件检测使用一个 50 帧（500ms）的环形缓冲区 accel_history[50][3]：

  • 轻拍检测回溯 10 帧，统计有多少帧超过阈值（≤5帧=真轻拍，>5帧=可能是摇晃开始）
  • 摇晃检测计数连续超过阈值的帧数，30 帧（300ms）后触发，同时回溯计算 X/Y 方差判定方向
  • 翻转检测计数 Z 轴持续反向的帧数，50 帧（500ms）后触发

8. 行为状态机

8.1 状态转移图

                    ┌─────────────────────────────────────┐
                    │              任何事件               │
                    ▼                                     │
  IDLE ──[水平摇]──> HAPPY                               │
  IDLE ──[垂直摇]──> SURPRISED ──[3s]──> CONFUSED ──[5s]──> IDLE
  IDLE ──[翻转]────> SURPRISED                           │
  IDLE ──[旋转]────> SURPRISED                           │
  IDLE ──[倾斜]────> CONFUSED                            │
  IDLE ──[连拍]────> SAD                                 │
  IDLE ──[捂热]────> WARM                                │
  IDLE ──[低温]────> COLD                                │
  IDLE ──[10s]────> BORED ──[30s]──> SLEEPY             │
                                                         │
  BORED/SLEEPY ──[任何事件]──> IDLE (先唤醒再处理事件)     │
  └─────────────────────────────────────────────────────┘

8.2 内部状态 vs 对外表情

状态机内部使用 behavior_state_t（STATE_IDLE, STATE_HAPPY, ...），通过 transition_to(state, emotion) 转换为对外的 emotion_t。两者分离的好处是：行为逻辑和面部表现可以独立演化。

8.3 空闲检查

check_idle() 每秒执行一次（behavior_task 的 xQueueReceive 超时触发），计算距上次事件的秒数：

  1. 如果当前是 SURPRISED 且已过 3s → 转 CONFUSED
  2. 如果当前是 CONFUSED 且已过 5s → 转 IDLE
  3. 如果距上次事件 > 30s → 转 SLEEPY
  4. 如果距上次事件 > 10s 且当前是 IDLE → 转 BORED

表情切换但无动画LVGL tick 定时器未启动检查 main.c 中 esp_timer 是否正确创建（1000us 周期）
动画卡顿渲染耗时太长降低帧率 (DISPLAY_FRAME_MS 50→100) 或检查 SPI 速率
栈溢出 (Guru Meditation)task 栈不够增大对应 task 的 STACK 值（harti_config.h），每次加 512 字节测试
按键不切换 spriteGPIO0 被温度 ADC 独占app_input.c 同时用 GPIO 数字读取 + ADC 读取，确保 ADC1 配置不冲突
sprite 切换后画面异常新 sprite 的 eye_radius 等参数不匹配检查 sprite 的 eye_radius / eye_half_spacing / mouth_y_center 等布局参数

11.5 调试技巧

  1. 看日志级别：修改 sdkconfig 中 CONFIG_LOG_DEFAULT_LEVEL 为 Debug 可以看到更详细的输出
  2. IMU 数据实时查看：串口 monitor 每 0.5s 输出原始加速度+陀螺仪数据，用来看阈值是否合理
  3. 单独测试 sprite：修改 face_api.h 中 face_init() 的默认 sprite，重启即可看效果
  4. 栈使用量：启用 CONFIG_FREERTOS_GENERATE_RUN_TIME_STATS 和 uxTaskGetStackHighWaterMark() 查看各任务实际栈使用
  5. 单独测试某个表情：在 main.c 的 display_task 开头直接调用 face_set_expression(N)，绕过传感器
